## 1. Mission (한 줄 결론)

**"V1에서 누적된 빌드 1,000+ 와 댓글 5,000+ 자산 위에 빌드 시뮬레이터 + 진령 채용률 차트 + Pain Point NLP 클러스터링 + 프리미엄 구독(₩4,900/월) + 다국어(JP/EN)를 도입해 P3 정보수집형 페르소나를 활성화하고, M15 시점 DAU 5,000+ / 빌드 10,000+ / 매출 ₩700K-1M/월의 V3 진입 졸업 KPI를 달성한다."**

Sprint V2는 V1까지 누적된 UGC raw 데이터를 인터랙티브한 인사이트 자산으로 변환한다. 빌드 시뮬레이터는 인벤이 만들 수 없는 차별점이며, 프리미엄 구독은 V3 B2B 영업의 매출 베이스라인이 된다. 다국어는 한국 단독 출시 게임의 제약을 V3 시점에 후속작 글로벌 출시 시 재활용하기 위한 사전 인프라.

## 3. In Scope (Master Plan §1 SCOPE(V2))

### 3.1 빌드 시뮬레이터 (F3.1)
- 진령 3선택 (11종 카드 클릭) → 시너지 자동 계산 → 점수 + 시각화 출력
- 시너지 계산 알고리즘: 직업×진령 매트릭스 + 진령 간 시너지 (운영자가 11×11 매트릭스 미리 작성)
- 결과 공유 URL: `/simulator/result/[id]` (시뮬레이션 영구 보존)
- 결과 → 빌드 작성으로 변환 (1-click)
- 무료/프리미엄 분기: 무료는 일 5회 한도, 프리미엄은 무제한

### 3.2 진령 채용률 차트 (F3.2)
- Firestore `builds` 컬렉션 집계 → Cloud Functions 일간 배치 → BigQuery export
- 차트: Chart.js 또는 Recharts (Lighthouse 영향 검토 후 선정)
- 주간 추이 (52주) + 신규 진령 출시 후 채용률 시계열
- 직업별 필터 (검객 메타 vs 영매 안정)

### 3.3 결투장 빌드 트렌드 (F3.3)
- `builds.tags` 필터 (`tags.contains('pvp')`)
- 좋아요 수 + 작성 빈도로 인기 PvP 빌드 TOP 10 자동 업데이트
- 주간 변동 비교 (메타 변화 시그널)

### 3.4 쿠폰 유효성 자동 검증 (F3.4)
- V1에서 도입된 `coupons.reported_invalid_count` 활용
- 커뮤니티 제보 (사용자가 쿠폰 만료 신고) → 3건+ 시 자동 `status: 'unknown'` 변경 → 운영자 알림
- 운영자 admin UI에서 일괄 확인 → `status: 'expired'` 또는 `status: 'valid'`로 수정

### 3.5 Pain Point NLP 클러스터링 (F3.5)
- V1 raw 데이터 1,200+ 건 입력 → 토픽 추출
- 옵션 A: OpenAI API (gpt-4o-mini, 비용 효율) — V2 권장
- 옵션 B: 자체 KoBERT (Cloud Run + GPU, 초기 비용 큼)
- 일간 배치 (Cloud Functions Scheduled) → `pain_topics` 컬렉션 토픽 + sentiment + frequency 업데이트
- `/insights/pain-points` 페이지에서 시각화

### 3.6 프리미엄 구독 결제 (F3.6)
- 구독 가격: **₩4,900/월** (PRD 02-strategy 가격 안정성 검증 결과)
- 결제 옵션: Stripe (글로벌) + 토스페이먼츠 (국내 결제 한국 시장)
- 혜택:
  - 빌드 시뮬레이터 무제한
  - 시즌패스 ROI 계산기 활성 (V2 후반 추가)
  - 광고 제거
  - Pain Point 토픽 상세 분석
  - 채용률 차트 12개월 시계열 (무료는 4주)
- 7일 무료 체험 + 언제든 취소
- 결제 자동 갱신 + 만료 7일 전 이메일 알림

### 3.7 다국어 JP/EN (F3.7)
- next-intl 라이브러리 도입
- URL 구조: `/jp/...` / `/en/...` (`/` 한국어 기본)
- 콘텐츠 9섹션 + 진령 11종 + 검객 메타 빌드 → JP/EN 번역
- UI 텍스트 i18n
- 후속작 글로벌 출시 시 재활용 가능 인프라

## 7. User Stories (PRD 04 §7.4 매핑)

### 7.1 V2-1: 빌드 시뮬레이터 (F3.1)
- As a P1·P3, I want to 진령 3개를 클릭으로 선택하면 시너지를 시각화로 보고 싶다, So that 텍스트 가이드보다 직관적이다.
- 수용 기준:
  - [ ] 11종 진령 카드 클릭 → 3선택까지 가능 (선택 토글)
  - [ ] 3선택 시 자동 시너지 계산 + 점수 + 시각화 출력 (1초 내)
  - [ ] 결과 공유 URL (`/simulator/result/[id]`)
  - [ ] 결과 → "이 빌드로 작성하기" 1-click 전환

### 7.2 V2-2: 진령 채용률 차트 (F3.2)
- As a P3, I want to 신규 진령 출시 48시간 채용률을 차트로 보고 싶다, So that "써볼만한가?" 빠른 판단.
- 수용 기준:
  - [ ] 11종 진령 × 52주 시계열 차트
  - [ ] 직업별 필터 (검객/전사/영매)
  - [ ] 신규 진령 출시 후 48시간 채용률 highlight

### 7.3 V2-3: 시즌패스 가성비 계산기 (V2 후반)
- As a P3, I want to 시즌패스 가격 + 보상을 입력하면 ROI를 보고 싶다, So that 과금 의사결정.

## 8. Pre-mortem (5종)

### 8.1 시나리오 A: 시뮬레이터 시너지 매트릭스 부정확 (확률 중)
- **증상**: 운영자가 작성한 11×11 시너지 매트릭스가 게임 실제 메타와 다름 → P1/P3 신뢰 하락 → 시뮬레이터 PV -50%
- **사전 방어**: V1 빌드 1,000+ 데이터 기반 통계적 시너지 검증 + 운영자 게임 플레이 검수
- **사후 대응**: 시뮬레이터 점수에 "운영자 가이드 + 커뮤니티 데이터" 출처 명시 + 매주 업데이트

### 8.2 시나리오 B: NLP 비용 폭증 (확률 저-중)
- **증상**: OpenAI API 비용 월 ₩50K+ → BUDGET_EXCEEDED 트리거
- **사전 방어**: 일간 배치만 (실시간 X), gpt-4o-mini 사용, 토픽 수 50개 한도
- **사후 대응**: KoBERT 자체 호스팅으로 전환 (Cloud Run + GPU 필요 시 비용 분석)

### 8.3 시나리오 C: 구독 전환율 1% 미만 (확률 중)
- **증상**: 7일 체험 → 결제 전환율 30% 목표 → 실측 1% → 매출 ₩300K도 어려움
- **사전 방어**: Phase plan에서 가격 ₩4,900 추가 검증 (사용자 인터뷰), 혜택 5종 매력도 사전 검증
- **사후 대응**: 가격 ₩2,900 인하 또는 혜택 추가 (예: 빌드 추천 AI)

### 8.4 시나리오 D: 다국어 트래픽 0% (확률 고 60%+)
- **증상**: 갓깨비 키우기는 한국 단독 출시 → 일본/영어 검색 키워드 0건 → 트래픽 0%
- **사전 방어**: Phase plan에서 다국어 우선순위 P2로 격하 + 후속작 글로벌 출시 시 활성화 옵션
- **사후 대응**: V2 후반에 다국어 비활성 결정 (M15 졸업 KPI에서 제외)

### 8.5 시나리오 E: Firestore 비용 폭증 → Blaze plan 비용 ₩100K+/월 (확률 중 40%)
- **증상**: DAU 3K+ 도달 시 Firestore reads 일 100K+ → Spark 한도 초과 → Blaze 전환 후 비용 폭증
- **사전 방어**: V1에서 Giscus 마이그레이션 완료 + V2에서 시뮬레이터/차트는 정적 캐싱 + Cloud CDN
- **사후 대응**: 구독 매출이 비용 ¼ 이상 유지하는지 모니터링
