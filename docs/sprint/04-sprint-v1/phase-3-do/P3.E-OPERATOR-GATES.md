# P3.E 운영자 게이트 — 카카오 OAuth 본격 활성화

> **Sprint V1 P3.E** — Kakao Developers 비즈니스 앱 전환
> Sprint v2 P3.A에서 Custom Token bridge 코드는 이미 작성 완료. 본 게이트는 운영자 1인 작업.

## 사전 상태

- ✅ `lib/auth/kakao.ts` — `kapi.kakao.com` → Firebase Custom Token bridge
- ✅ `app/api/auth/kakao-exchange/route.ts` — 교환 endpoint
- ✅ NextAuth Kakao provider (lib/auth/config.ts)
- ✅ JWT.accessToken 영속화 (Sprint V1 P5 m4 cast 제거)

→ **코드 변경 없음**. Vercel env + 카카오 콘솔 작업만 필요.

## 작업 흐름 (대기 ~7일)

### 1. 카카오 디벨로퍼스 가입

https://developers.kakao.com/

- Google 계정 또는 카카오 계정으로 가입
- 운영자 (kay@agentkay.it) 본인 명의

### 2. 애플리케이션 생성

- "내 애플리케이션 → 애플리케이션 추가하기"
- 앱 이름: `깨비지기` 또는 `갓깨비 키우기 비공식 가이드`
- 사업자명: kay@agentkay.it 개인사업자 (또는 법인)

### 3. 비즈니스 앱 전환

개인 앱 → 비즈니스 앱:
- "앱 설정 → 비즈니스 정보" 진입
- 사업자 등록증 사본 업로드 (또는 개인사업자 사업자등록증)
- 검토 대기 (~3-7일)

### 4. 동의 항목 설정

"제품 설정 → 카카오 로그인 → 동의 항목":
- **이메일** — 필수 (Firebase Auth 매핑용)
- **닉네임** — 필수 (NextAuth user.name)
- **프로필 이미지** — 선택

### 5. Redirect URI 등록

"제품 설정 → 카카오 로그인 → Redirect URI":
- `https://{도메인}/api/auth/callback/kakao`
- 도메인 G4 결정 후 등록

### 6. Vercel env 갱신

```
KAKAO_REST_API_KEY=<발급된 REST API 키>
KAKAO_CLIENT_SECRET=<발급된 Client Secret — 보안 강화 시 활성화>
```

### 7. 검증 (Chrome MCP)

1. production deploy 후 `/login` 진입
2. "카카오로 시작하기" 클릭
3. 카카오 인증 화면 → 동의 → callback `/api/auth/callback/kakao`
4. `/api/auth/kakao-exchange` 자동 호출 → Firebase Custom Token 발급
5. `/register` 폼 진입 (미등록 사용자) 또는 `/` 진입 (등록 사용자)
6. `?login=success&method=kakao` URL 부착 확인 → GA4 `login` 이벤트 발화

## 사용자 시나리오 (P6 QA S2)

| Step | 위치 | 검증 |
|---|---|---|
| 1 | `/login` 진입 | AuthButtons + "카카오로 시작하기" 표시 |
| 2 | Kakao OAuth | NextAuth signIn('kakao') → kapi.kakao.com redirect |
| 3 | callback | `/api/auth/callback/kakao` → JWT.accessToken 저장 |
| 4 | bridge | `/api/auth/kakao-exchange` → Firebase Custom Token |
| 5 | redirect | `/?login=success&method=kakao` → LoginSuccessTracker `logEvent('login')` |
| 6 | 미등록 | `/register` → 4-table 트랜잭션 → claims {role: 'user', registered: true} |
| 7 | 등록 완료 | `/` 진입 + ChatWidget 마운트 + UserMenu 표시 |
